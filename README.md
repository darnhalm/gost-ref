# gost-ref

Формирование библиографических ссылок и записей по ГОСТ — детерминированно,
без «примерно так».

| ключ | стандарт | для чего |
|---|---|---|
| `7.0.5` | ГОСТ Р 7.0.5-2008 | библиографическая ссылка: подстрочные сноски, «Там же», «Указ. соч.», «Цит. по» |
| `7.0.100` | ГОСТ Р 7.0.100-2018 | библиографическая запись: список литературы, в том числе для ВАК |
| `7.1` | ГОСТ 7.1-2003 | прежний стандарт записи — некоторые журналы и советы всё ещё требуют его |
| `7.0.108` | ГОСТ Р 7.0.108-2022 | ссылки на сетевые электронные документы (действует вместе с 7.0.5) |

Одно ядро — три способа обращения: библиотека Python, командная строка, MCP-сервер.

## Установка

```bash
cd gost-ref
pip install -e ".[all]"      # ядро + MCP-сервер + чтение PDF
```

Ядро зависимостей не имеет. `mcp` нужен только серверу, `pypdf` — чтению PDF.

## Подключение как MCP

`claude_desktop_config.json` (или конфиг любого другого MCP-клиента):

```json
{
  "mcpServers": {
    "gost-ref": {
      "command": "python3",
      "args": ["/полный/путь/gost-ref/server.py"]
    }
  }
}
```

### Инструменты

| инструмент | что делает |
|---|---|
| `list_source_types` | типы источников и полный список полей — вызывать первым, если не уверены |
| `format_reference` | поля → строка по одному стандарту + проверка |
| `format_all_standards` | те же поля во всех четырёх стандартах |
| `reformat_reference` | кривая строка → строка по стандарту |
| `parse_reference` | строка → поля, без форматирования |
| `validate_reference` | проверка описания и/или готовой строки |
| `build_bibliography` | массив описаний → готовый список литературы |
| `repeat_reference` | «Там же», «Указ. соч.», «Цит. по», «См. также» |
| `lookup_metadata` | метаданные по DOI, ISBN, заглавию |
| `read_pdf_metadata` | выходные данные из PDF: титул, оборот титула, ISBN, УДК |
| `check_links` | ссылки на РИНЦ, РГБ, НЭБ, фонд Росстандарта для ручной сверки |

## Командная строка

```bash
gost-ref reformat -s 7.0.5 "Иванов И.И. Заглавие. М., 2020. 100 с."
gost-ref lookup 10.5406/ethnomusicology.58.3.0379
gost-ref pdf ~/книга.pdf
gost-ref list -s 7.0.100 < sources.json
echo '{"type":"book","title":"Заглавие","city":"Москва","year":"2020"}' | gost-ref format
```

## Тип источника: показ и правка

Тип не спрашивается кнопкой — он выводится из строки. Поэтому `reformat` и
`parse` возвращают не только ключ, но и объяснение:

```python
out = g.reformat("Лихачев Д. С. Образ города // Историческое краеведение. Киев, 1991. С. 183-188.")
out["type_label"]                       # 'глава книги или статья в сборнике'
out["type_detection"]["confidence"]     # 'средняя'
out["type_detection"]["reason"]         # 'есть «//», но нет номера выпуска'
out["type_detection"]["alternatives"]   # статья в журнале, материал на сайте
```

Уверенность: **высокая** — нашёлся служебный оборот («автореф. дис», «: официальный
сайт»); **средняя** — вывод по строению строки; **низкая** — ни одной приметы,
взят тип по умолчанию. При уверенности ниже высокой в `parse_notes` добавляется
предупреждение, а в ответе появляется `how_to_override`.

Поправить — одним параметром, поля пересобирать не нужно:

```bash
gost-ref reformat -s 7.0.100 --type article "Лихачев Д. С. Образ города // ..."
```

```python
g.reformat(raw, "7.0.100", type_override="article")
```

Это меняет результат: у главы сборника остаются город и год издания, у статьи в
журнале город уходит. Неизвестный тип не подставляется молча — возвращается
ошибка со списком допустимых.

## Сноска и запись — парой

В диссертации нужны обе формы, а поля у них одни и те же. Поэтому основной
режим отдаёт сразу и то, и другое, без вопроса «сноска или список»:

```bash
gost-ref pair < source.json
```

```python
r = g.format_pair(fields)                       # запись по 7.0.100
r = g.format_pair(fields, record_standard="7.1")  # если совет требует старый
r["footnote"]["text"]   # Лихачев Д. С. Русская культура. СПб. : Искусство, 2007. 440 с.
r["record"]["text"]     # Лихачев, Д. С. Русская культура / Д. С. Лихачев. — Санкт-Петербург : …
```

Сноска собирается по ГОСТ Р 7.0.5-2008; если у источника есть URL, применяется
уточняющий его ГОСТ Р 7.0.108-2022. Запись — по 7.0.100-2018 или 7.1-2003.
Каждая форма приходит со своими замечаниями валидатора.

В MCP это `format_footnote_and_record`.

## Как библиотека

```python
import gost_ref as g

g.format_reference({
    "type": "article",
    "authors": "Козаченко Ю. В.",
    "title": "Акариформные клещи в трудах отечественных исследователей",
    "container": "Аспирант и соискатель",
    "year": "2018", "issue": "2 (104)", "pages": "19-21",
}, "7.0.100")
# 'Козаченко, Ю. В. Акариформные клещи… / Ю. В. Козаченко. — Текст :
#  непосредственный // Аспирант и соискатель. — 2018. — № 2 (104). — С. 19–21.'

g.format_all(fields)          # все четыре стандарта разом
g.reformat(raw, "7.0.100")    # кривая строка → правильная + отчёт
g.build_list(items, "7.0.100")
g.ibid("25")                  # 'Там же. С. 25.'
```

`nbsp=True` ставит неразрывные пробелы в инициалах и после «С.», «№», «Т.» —
чтобы Word не разрывал их переносом строки.

## Что проверяет валидатор

Уровни: `error` — не соответствует стандарту; `warning` — почти наверняка ошибка;
`note` — стоит перепроверить руками.

- «Текст : электронный» у печатного издания и наоборот — самая частая системная
  ошибка списков по 7.0.100;
- URL без даты обращения; дата обращения в будущем или не в формате ДД.ММ.ГГГГ;
- сокращённое место издания в записи по 7.0.100 («М.» вместо «Москва»);
- отсутствие области вида содержания в записи по 7.0.100;
- разделители областей `— ` в подстрочной сноске (запись 7.0.100, попавшая в сноску);
- область вида содержания («Текст : непосредственный») — по ГОСТ Р 7.0.100-2018
  элемент факультативный, поэтому по умолчанию НЕ выводится и её отсутствие
  считается замечанием, а не ошибкой; включается `content_type=True`;
- дефис вместо короткого тире в диапазоне страниц, «И.И.» без пробела,
  двоеточие без пробела с любой стороны («М.: Наука» вместо «М. : Наука»),
  пропущенный пробел у «//», авторы в заголовке без запятой;
- у статьи нет журнала, тома/номера или страниц; у книги — города, издательства, объёма;
- у диссертации нет шифра специальности или степени;
- у ГОСТа нет обозначения; напоминание проверить его действующий статус.

## Внешние базы

Работают без ключа: **Crossref**, **DataCite** (DOI), **OpenAlex** (DOI и заглавие),
**OpenLibrary** и **Google Books** (ISBN), **КиберЛенинка** (русскоязычная периодика).

У **РИНЦ (eLibrary)**, **РГБ**, **НЭБ** и фонда стандартов **Росстандарта**
открытого API нет — `lookup_metadata` и `check_links` возвращают готовые ссылки
для проверки руками или браузерным инструментом.

Каждый ответ несёт поле `source` с адресом, откуда взяты данные. Ни одна функция
не додумывает поля: чего нет в ответе базы — того нет в результате.

## PDF

`read_pdf_metadata` отдаёт `/Info`, XMP, текст первых и последних страниц и
кандидатов в поля (ISBN, ISSN, УДК, ББК, DOI, город, год, тираж, дату подписания
в печать).

Две ловушки, о которых модуль предупреждает прямо в ответе:
`/Info` в PDF обычно заполнен конвертером («Microsoft Word - диплом.doc»),
поэтому приоритет — текст титульного листа и его оборота; число страниц файла
не равно объёму издания.

## Сверка с snoska.info

Онлайн-генератор snoska.info оформляет только по ГОСТ Р 7.0.5-2008 и поддерживает
восемь типов источников. Его собственный образец с сайта:

```
Пантелеев А.С. Звездин А.Л. Векселя, взаимозачеты: бухгалтерский учет
и налогообложение. – 4-е изд. – М.: Омега-Л, 2010. – 176 с.
```

Те же данные через `gost-ref -s 7.0.5`:

```
Пантелеев А. С., Звездин А. Л. Векселя, взаимозачеты : бухгалтерский учет
и налогообложение. 4-е изд. М. : Омега-Л, 2010. 176 с.
```

Четыре расхождения, все — в пользу стандарта: инициалы разделяются пробелом;
авторы в заголовке — запятой; двоеточие предписанной пунктуации окружено
пробелами с обеих сторон; тире между областями относится к записи по 7.0.100
и 7.1, а в подстрочной ссылке его нет. Валидатор ловит все четыре.
