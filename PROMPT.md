# Промпт для нового чата

Скопируйте текст ниже целиком в начало нового чата — дальше ассистент работает
по правилам проекта сам.

---

Работай по репозиторию https://github.com/darnhalm/gost-ref — это детерминированное
оформление библиографии по ГОСТ. Сначала прочитай в нём `skill/SKILL.md`,
`AGENTS.md` и `references/normative-policy.md`: это правила работы, а не справка.

Жёсткие правила, нарушать нельзя:

1. **Строку ссылки собирает только пакет `gost_ref`.** Руками не оформлять
   никогда, даже если кажется очевидным. Нет доступа к пакету — так и скажи,
   но не собирай сам.
2. **Отдавай обе формы сразу** — подстрочную сноску по ГОСТ Р 7.0.5-2008 и
   запись для списка литературы по ГОСТ Р 7.0.100-2018. Основной вызов —
   `format_footnote_and_record` (в CLI `pair`). Не спрашивай «сноска или список».
3. **Называй тип источника по-русски** (`type_label`) рядом со ссылкой и
   показывай замечания валидатора. Ключи вроде `chapter` пользователю не
   показывай — они только для вызова.
4. **Любой URL или DOI перед выдачей открой сам** браузерным инструментом и
   сверь: искомый автор — именно автор публикации, заглавие совпадает. Не
   через `curl` — научные базы блокируют не-браузерные запросы. Не открылось
   или не то — ссылку не выдавать, сказать прямо.
5. **Недостающие поля сначала искать** через `lookup_metadata`, и только потом
   спрашивать меня — показав, что именно поиск вернул.
6. **Критика моего варианта — только с номером пункта стандарта и цитатой.**
   Не помнишь пункт — проверь текст стандарта, а не придумывай «общий принцип».

Как добраться до пакета, по убыванию предпочтения:

- **Подключён MCP-сервер `gost-ref`** — просто пользуйся его инструментами.
  Ничего скачивать и запускать не надо, сеть не нужна.
- **Есть shell и папка репозитория** — вызывай ядро прямо в ней:

  ```bash
  cd ~/gost-ref && echo '{"type":"article","authors":"Иванов И. И.","title":"Заглавие","container":"Журнал","year":"2020","issue":"3","pages":"5-12"}' | python3 -m gost_ref.cli pair
  ```

  Зависимостей у ядра нет, `pip install` не нужен.
- **Есть shell и сеть до GitHub** — склонируй и работай так же:

  ```bash
  if [ ! -d ~/gost-ref ]; then git clone -q https://github.com/darnhalm/gost-ref.git ~/gost-ref; fi
  ```

- **Ничего из этого нет** — скажи об этом сразу, в первом же ответе, не после
  нескольких попыток. Ручная сборка запасным вариантом не является.

Если в этом аккаунте ещё не сохранён навык `gost-references` — предложи
сохранить его из `skill/SKILL.md`, чтобы в следующих чатах не повторять этот
промпт.

## Как сделать, чтобы промпт не требовался

**Удалённый сервер — главный способ.** Он и нужен затем, чтобы оформление
работало в обычном чате, где нет ни shell, ни сети до пакета. Подключается
один раз на уровне пользователя и виден во всех новых чатах:

```bash
./scripts/connect-remote.sh
```

Скрипт сам достанет адрес и токен из Yandex Cloud, проверит сервер и выполнит
`claude mcp add --scope user`. Вручную это выглядит так:

```bash
claude mcp add --transport http gost-ref --scope user \
  https://<container-id>.containers.yandexcloud.net/mcp \
  --header "X-API-Key: <токен>"
```

Заголовок именно `X-API-Key`: Yandex Serverless Containers проверяет
`Authorization` как свой IAM-токен и отвечает `403` раньше, чем запрос дойдёт
до контейнера. На других площадках работает и `Authorization: Bearer`.

Клиенты, где заголовок задать нельзя (веб-интерфейс claude.ai для собственных
коннекторов), требуют OAuth — для них нужен внешний шлюз. Через API OpenAI
сервер подключается полем `authorization` в описании MCP-инструмента.

**В Claude Code и Cowork со своей папкой** работает и локальный путь: в корне
репозитория лежит `.mcp.json`, клиент подхватит сервер сам и спросит
подтверждение. MCP SDK доустановится при первом запуске в `.venv-mcp` внутри
репозитория.

**Навык.** Сохранённый один раз в аккаунте навык `gost-references` срабатывает
на слова «сноска», «список литературы», «оформить источник» в любом новом чате.
Он не заменяет доступ к пакету, а задаёт порядок работы с ним.
