# Библиографические ссылки по ГОСТ

Сборку строки делает пакет `gost_ref` (детерминированно), а не модель. Твоя работа — правильно определить тип источника и добыть выверенные поля.

## Порядок работы — не менять

1. **Определи тип.** `book`, `chapter`, `article`, `dissertation`, `abstract`, `standard`, `law`, `treaty`, `website`, `webpage`, `archive`, `media`, `preprint`.
2. **Сначала открой предоставленный документ** и проверь, что это нужное произведение и издание. Собери поля по порядку ниже; текст таблицы и имя файла используй для сверки, а не вместо страниц.
3. **Недостающее — доищи**: сначала в доступных страницах документа, затем на странице этого издания у издателя или в библиотечном каталоге, затем через `lookup`. Если документ уже даёт все нужные сведения без противоречий, дополнительный поиск не обязателен. Вопрос задавай о том, чего доступные источники не прояснили, указав фактически выполненные проверки. Для восстановления доступа к закрытому файлу допустимо сразу попросить доступ, продолжая независимую проверку доступных материалов.
4. **Прогони через ядро** — руками строку не собирать.
5. **Отдай обе формы** — сноску и запись для списка.
6. **Назови тип по-русски**, покажи замечания валидатора и всё, что пришлось предположить или дополнить извне.

## Сноска и запись — всегда парой

**Не спрашивай «сноска или список».** В работе нужны обе формы, а поля у них одни и те же. Основной вызов — `format_footnote_and_record` (в CLI `gost-ref pair`): он отдаёт подстрочную сноску по 7.0.5-2008 (для сетевого документа её уточняет 7.0.108-2022) и запись по 7.0.100-2018 сразу.

Одну форму вместо пары бери только когда пользователь прямо сказал, что нужна именно она. Если совет требует старый стандарт — `record_standard="7.1"`, пара при этом сохраняется.

## Норма стандарта и настройки проекта

Перед оформлением прочитай `AGENTS.md` и `references/normative-policy.md` в корне пакета: там правила проверки источников и нормативной аргументации. Настройки программы и уровни её замечаний не заменяют требования стандарта. При противоречии сверяй первичный текст, а не выбирай удобную формулировку из README или теста.

- **Вид содержания** — условно-обязательный элемент по п. 5.10.4; средство доступа — по п. 5.10.8. Не путай их с факультативной характеристикой содержания (п. 5.10.7). По п. 4.4.2 применение условно-обязательных элементов зависит от идентификации ресурса и задач библиографирующей организации. `content_type=False` — сохранённая настройка проекта, а не утверждение о факультативности области. Включай `content_type=True`, когда этого требуют заданный профиль описания или требования организации; применяй выбор последовательно ко всему списку.
- **Точка и тире между областями** (`. — `). П. 4.6.4 допускает замену точкой при выделении областей шрифтами или с новой строки. Это не безусловное разрешение для обычной строки. `no-area-dash` имеет уровень `note`, поскольку валидатор не видит оформление документа; сверяй его перед выводом о соответствии.
- **Сокращение места издания.** В 7.0.100 принято «Москва», в 7.0.5, 7.1 и 7.0.108 — «М.». Но прямого запрета на сокращение в тексте 7.0.100 нет, поэтому валидатор об этом предупреждает, а не бракует.

Уровни `error`, `warning`, `note` задают приоритет проверки в программе, а не обязательность элемента по ГОСТу. `ok=true` означает отсутствие обнаруженных ошибок уровня `error`; это не полная нормативная экспертиза и не проверка URL. Не превращай каждое `note` в предупреждение пользователю, но учитывай его, если оно существенно для заданных требований.

## Тип источника: показать и дать поправить

Тип меняет готовую строку. У главы сборника остаются город и год издания, у статьи в журнале город уходит. Поэтому молча принятый тип — тихая ошибка.

В ответе `reformat`, `parse` и `pair` есть `type_label` (тип по-русски), а у первых двух ещё и `type_detection` — `confidence` (высокая / средняя / низкая), `reason` и `alternatives`. Правила:

- **Всегда называй тип по-русски** рядом со ссылкой. Никогда не показывай пользователю ключи вроде `chapter` — они только для вызова.
- **При `confidence` ниже высокой** скажи, почему тип выбран, и одной строкой предложи альтернативы из `alternatives`.
- **Чтобы поправить** — тот же вызов с `type_override` (в CLI флаг `--type`). Пересобирать поля заново не нужно.
- Когда пользователь назвал тип сам — передавай его сразу, не давая определителю гадать.

Определитель точно не различает: главу сборника и доклад в материалах конференции (обе — `chapter`); газетную статью от журнальной; препринт не опознаёт вовсе. В этих случаях задавай тип явно.

## Где взять пакет

Если подключён MCP-сервер `gost-ref` — пользуйся его инструментами, больше ничего не нужно.

Иначе пакет берётся из репозитория. Среда часто временная, поэтому проверь наличие пакета; клонируй только при его отсутствии. Обновление существующего кода — отдельное действие с проверкой локальных изменений и последующей синхронизацией установленного навыка:

```bash
if [ ! -d ~/gost-ref ]; then git clone -q https://github.com/darnhalm/gost-ref.git ~/gost-ref; fi
```

У ядра нет обязательных зависимостей — после клонирования оно работает сразу, `pip install` не нужен. Он понадобится только для чтения PDF (`pip install pypdf`) и для MCP-сервера.

Если сети нет и клонировать не вышло — скажи об этом и попроси приложить архив к чату. Строку вручную не собирай ни при каких обстоятельствах: в этом весь смысл навыка.

## Вызов ядра

```bash
cd ~/gost-ref && echo '{"type":"article","authors":"Козаченко Ю. В.","title":"Заглавие","container":"Аспирант и соискатель","year":"2018","issue":"2 (104)","pages":"19-21"}' | python3 -m gost_ref.cli pair
```

Остальные команды: `format -s 7.0.100` (одна форма), `all` (все четыре стандарта), `reformat "кривая строка"` (с `--type chapter`, если тип определён неверно), `parse`, `list < sources.json`, `lookup <DOI|ISBN|заглавие>`, `catalog-search <ISBN|заглавие>`, `catalog-record <id>`, `pdf <путь>`. Флаги ставятся ПОСЛЕ подкоманды: `--nbsp` — неразрывные пробелы для Word, `--content-type` — включить область вида содержания и средства доступа, `--record 7.1` у `pair`. Параметр `content_type` поддерживают `format`, `pair`, `all`, `reformat`, `list` и соответствующие API/MCP-вызовы; он меняет только запись по 7.0.100.

## Какой стандарт

| ключ | когда |
|---|---|
| `7.0.5` | подстрочные сноски в тексте работы |
| `7.0.100` | список литературы, диссертации и статьи для ВАК |
| `7.1` | если журнал или совет прямо требует старый стандарт |
| `7.0.108` | сетевые электронные документы; действует вместе с 7.0.5 |

По умолчанию — пара 7.0.5 + 7.0.100, выбирается автоматически. Спрашивать про 7.1 имеет смысл только при прямом признаке, что совет требует старый стандарт.

## Откуда берутся поля

### Приоритет доказательств для конкретного издания

1. **Сам предоставленный документ**: у книги — титульный лист, оборот титула и выходные сведения; у статьи — первая страница, сведения о выпуске и страницы статьи. Первые страницы PDF могут быть обложкой или предисловием: найди именно нужные страницы. При необходимости проверь конец книги для выходных данных и объёма.
2. **Издатель или библиотечный каталог**, описывающий то же издание: для дополнения и разрешения расхождений.
3. **Поисковые базы (`lookup`)**: для поиска недостающих данных и кандидатов, которые ещё нужно сверить.

Это приоритет для библиографических данных, а не гарантия истинности всех утверждений в книге. Приложенный файл не считается достоверным автоматически: сопоставь автора, заглавие, год, номер издания, ISBN или обозначение редакции стандарта. Не смешивай поля разных изданий. Действующий статус стандарта проверяй отдельно — старый PDF его не подтверждает.

**PDF и скриншоты.** Читай содержание страниц; `pdf <путь>` или `read_pdf_metadata` помогает извлечь текст. Если текстового слоя нет, он повреждён или сомнителен, просмотри изображения нужных страниц. OCR, имя файла, `/Info` и XMP — подсказки, не основание переопределить отчётливо читаемый титул. Не достраивай город по издательству и не разворачивай инициалы. Неразборчивое помечай как неопределённое. Число страниц файла не равно объёму издания; проверяй печатную пагинацию и выходные сведения.

**Таблица со ссылками на документы.** Используй таблицу как указатель: прочитай заголовки и фактические ссылки/файловые чипы в указанной пользователем колонке, затем открой сами документы через доступный Drive-коннектор или браузер. Не ограничивайся отображаемым именем PDF. Связывай результат с листом и строкой. В сценарии пользователя со второй колонкой документов первая колонка — запись для сверки, а не подтверждённые выходные данные. Номера колонок и конкретную таблицу не переносить на другие задачи без проверки. Доступ к таблице не означает доступ к каждому вложению. Саму таблицу изменяй только по запросу пользователя.

**Происхождение и расхождения.** Для извлечённых полей сохраняй источник проверки и страницу PDF (при наличии — также печатный номер); общую ссылку на страницу можно указать сразу для группы полей. Например: «автор, заглавие — титул, страница PDF 3; издательство, год, ISBN — оборот, страница PDF 4». Внешние дополнения отмечай отдельно. При конфликте покажи оба значения и их происхождение, проверь различие изданий. Для описания приложенного издания предпочитай его читаемые выходные данные; если они противоречат друг другу или соответствие издания не установлено, не выбирай молча и не объединяй записи.

Ссылка Drive служит доступом к экземпляру для проверки. Не подставляй её автоматически в библиографическую запись и не объявляй печатную книгу сетевым изданием только потому, что её скан хранится в Drive.

**DOI, ISBN, заглавие.** `lookup`. Какие базы опрашиваются — зависит от того, что на входе:

| на входе | опрашиваются автоматически |
|---|---|
| DOI | Crossref, затем DataCite, затем OpenAlex |
| ISBN | OpenLibrary, Google Books |
| заглавие | OpenAlex, Crossref (`query.bibliographic`), КиберЛенинка |

Это порядок попыток: `lookup` останавливается на первом успешном результате. Сверяй кандидата по автору и заглавию; не утверждай, что проверены все базы, если результат этого не подтверждает. `attempts` содержит неудачные попытки, `source` — успешный источник. Несовпадение кандидата — повод продолжить поиск, а не принять первую запись.

В ответе есть `source` — приводи его пользователю. Пустой результат означает только «в этих базах нет», а не «источника не существует»: издания без DOI (бюллетени комитетов, музейные сборники, ведомственные записки) в этих индексах отсутствуют по определению.

**Издания книг и неоднозначные ISBN.** После `lookup`, если нужно найти конкретное издание или сравнить каталожные записи, вызови `search_catalog` (в CLI `catalog-search`). Он возвращает кандидатов из Open Library, WorldCat, ISBNdb, Google Books и других каталогов. Сравни заглавие, авторов, год и издание; не выбирай первую строку молча. Для выбранного `id` вызови `get_catalog_record` (в CLI `catalog-record`) и лишь затем передавай `fields` в `format_footnote_and_record`.

Каталожный поиск не скачивает файлы и не возвращает файловые хеши. `record_url`, DOI, ISBN и другие идентификаторы из ответа — не готовая ссылка, а подсказка: перед выдачей открой карточку браузером и сверь автора и заглавие по правилу zero-trust ниже.

**Telegram-бот.** Бот в репозитории использует те же MCP-вызовы для каталожного поиска, подробной записи и форматирования пары. Его ответ не повышает надёжность кандидата: автора и заглавие всё равно нужно сверить перед цитированием. Дополнительный поиск Academia.edu возвращает только ссылки-кандидаты из веб-поиска; кнопка ГОСТ сначала сверяет заглавие через `lookup`. При ручном запуске на Mac отдельный локальный адаптер может сохранить уже доступные пользователю страницы через `academiadl-py`; эта функция не входит в MCP, не работает в облачном Telegram-контейнере и не получает ключ Anna.

**Anna's Archive в навыке (поиск книг и статей).** Не ограничивай поиск Anna Telegram-ботом. При запросах «найди в Архиве Анны», «поищи книгу/статью», «проверь другие издания» используй доступные инструменты, а не отвечай, что навык умеет только Academia.edu:

1. В MCP `gost-ref` вызови `search_catalog` (CLI: `gost-ref catalog-search`) с названием или ISBN; для выбранного кандидата вызови `get_catalog_record` (CLI: `gost-ref catalog-record <id>`). В проекте эти вызовы используют `annas-mcp` как **агрегатор каталожных метаданных**, а не как интерфейс скачивания. Результат может происходить из Open Library, WorldCat, ISBNdb, Google Books или другого каталога; **не называй его результатом непосредственно Anna's Archive**, если источник этого не подтверждает.
2. Если в текущем MCP-клиенте **отдельно подключён** сервер `annas-mcp` и доступны инструменты поиска книг или статей (например, `book_search`, `article_search`), используй их для **прямого поиска в Anna's Archive**. Определи точные имена и параметры по доступной схеме инструментов; не выдумывай вызовы и не утверждай, что отдельный сервер подключён, пока он не обнаружен.
3. Если отдельный `annas-mcp` недоступен, прямо разграничь: «поиск по каталогам через gost-ref доступен; прямой поиск Anna's Archive требует отдельного MCP-подключения». Предложи подключить сервер в Claude Desktop, не запрашивая API-ключ для обычного поиска, если он не нужен по документации установленной версии.
4. Для статьи сначала пробуй DOI/название через `lookup_metadata`, а при доступности прямого `annas-mcp` — поиск статей; для книги используй ISBN/название и каталожный поиск. Academia.edu через `search_academia` остаётся независимым дополнительным источником кандидатов. Не выдавай поиск в одной базе за поиск во всех.
5. Результаты Anna и каталогов — **кандидаты**, не проверенные библиографические записи. Сверяй автора, название, год, издание и идентификаторы по титулу/издателю/библиотечному каталогу; не смешивай издания. Для пользователя указывай, где реально выполнен поиск и что подтверждено. Не добавляй в навык функции скачивания, обхода ограничений доступа или работу с секретными ключами.

**Academia.edu в MCP.** `search_academia` возвращает только заглавия и прямые ссылки-кандидаты на страницы документов; он не скачивает файлы и не извлекает полный текст. Перед цитированием открой выбранную страницу, сверь автора и заглавие, затем дополни поля через `lookup_metadata`. Наличие ссылки в выдаче не является проверкой источника.

**РГБ — обязательная браузерная проверка российских изданий.** Для российских книг, диссертаций, дореволюционных изданий и работ без DOI после проверки документа и автоматических каталогов открывай официальный электронный каталог РГБ: https://search.rsl.ru/ (описание сервиса: https://www.rsl.ru/elektronnye-resursy/elektronnyy-katalog/). Ищи по точному заглавию, затем по сочетанию фамилии автора и ключевых слов; при необходимости уточняй год и вид документа. Это **реальный поиск через браузер**, а не вызов несуществующего `rsl_search` или неподтверждённого API. Если браузер недоступен, используй `check_links` для получения поисковой ссылки и явно помечай «РГБ не проверена». Сверяй на открытой карточке автора, полное заглавие, год, место издания, издателя, объём и конкретное издание; фиксируй ссылку на **проверенную карточку**, а не ссылку на общую выдачу. Если запись не открылась или доступ ограничен, не объявляй данные проверенными. Каталожная карточка не заменяет титульный лист доступного экземпляра. Поиск в РГБ не означает, что книгу можно скачать. Для старых изданий учитывай, что отдельные документы могут находиться только в карточных/имидж-каталогах.

**РИНЦ/eLibrary, РГБ, НЭБ, Росстандарт — НЕ ищутся автоматически.** У них нет открытого API и они режут не-браузерные запросы. `lookup` возвращает по ним блок `manual_checks` — готовые поисковые адреса, которые надо открывать браузером и сверять глазами.

**РИНЦ, РГБ, НЭБ, статус ГОСТа.** Открытого API нет. `check_links` даёт ссылки; открой их браузерным инструментом или отдай пользователю. Не выдавай данные из этих баз, не посмотрев.

**Что дополнил — скажи явно.** Каждое поле, взятое не от пользователя, назови вместе с базой. **Если данных не нашлось нигде** — так и скажи: перечисли недостающие поля и покажи, что собралось без них. Не подставляй правдоподобное и не молчи о пробеле.

## Ссылки: zero-trust к сниппетам

URL, DOI и идентификатор каталога (РГБ, НЭБ, РИНЦ, Crossref) в сниппете поисковой выдачи — это ещё не источник, а подсказка, которую надо проверить. Сниппет часто подсовывает статью **стороннего автора**, который лишь цитирует искомую работу, или **устаревший/битый** адрес (404 / редирект / смена CMS).

**Запрещено копировать ссылку или идентификатор из сниппета прямо в ответ.** Прежде чем дать пользователю любой URL или DOI:

1. **Открой его сам** — для приложенного файла допустим авторизованный коннектор с чтением страниц; для внешней веб-страницы — браузерным инструментом (или `check_links` → браузер). **Не** через `curl`/`wget`/скрипт с HTTP-запросом: научные базы (РГБ `search.rsl.ru`, eLibrary, РИНЦ, `protect.gost.ru`, `docs.cntd.ru`) блокируют не-браузерные запросы и адреса дата-центров — код ответа там ничего не доказывает, живая страница легко отдаёт 403/timeout. DOI резолвь через `doi.org`.
2. **Сверь на открывшейся странице:** искомый автор присутствует именно как **автор публикации**, а не как случайная цитата в чужом тексте; заглавие на странице **совпадает** с проверяемым источником.
3. **Не открылось / заблокировано / не тот материал — ссылку не давать.** Прямо скажи: «прямой URL не открывается (404 / смена CMS / блокировка)». Затем либо найди и **так же проверь** рабочее зеркало (КиберЛенинка, eLibrary), либо явно обозначь неполноту записи. Печатную версию описывай только при наличии данных этой версии.

Идентификатор без проверки — не идентификатор. Предлагая ссылку, коротко подтверди, что открыл её и сверил автора и заглавие.

## Чего не делать никогда

- Не выдумывать издательство, город, объём, номер выпуска, страницы. Пустое поле лучше правдоподобной подстановки: неверные выходные данные в списке — основание для замечания на защите.
- Не копировать URL/DOI из сниппета поисковика, не открыв страницу и не сверив автора и заглавие (см. «Ссылки: zero-trust к сниппетам»).
- Не ставить дату обращения задним числом. Если её нет — либо сегодняшняя (ты правда открыл ссылку сейчас), либо спроси.
- Не переводить и не транслитерировать заглавия.
- Не выдавать статус ГОСТа по памяти. Проверяй статус и применимость редакции в фонде Росстандарта; не представляй отменённую редакцию действующей. Сам факт цитирования исторической редакции не означает ошибку.

## Ловушки, на которых горят списки

1. **URL без даты обращения.** Проверяй требования применяемого стандарта; для электронных журналов в 7.0.100 п. 5.8.6.4 г) допускает дату публикации вместо даты обращения. Уровень замечания программы не отменяет требования.
2. **Четыре автора и больше** в 7.0.100 и 7.1: заголовок записи не применяется, описание начинается с заглавия, все четверо идут после `/`. При одном–трёх авторах заголовок — первый автор, но после `/` всё равно перечисляются все.
3. **Тире между областями (`. — `) есть только в 7.0.100 и 7.1.** В подстрочной сноске его нет — области разделяются точкой. Запись из списка, вставленная в сноску, видна сразу.
4. **Если область вида содержания всё-таки затребовали** у составной части — она стоит ПЕРЕД `//`: `… / Ю. В. Козаченко. — Текст : непосредственный // Журнал. — 2018.` Схема и примеры — ГОСТ Р 7.0.100-2018, п. 7.1.4. В хвосте, после пагинации, стоят примечания (URL, дата обращения) по п. 7.5.1, а не вид материала. У описания издания целиком область идёт в конце (п. 4.3 — в перечне областей она последняя).
5. **Сиротский «Текст : электронный» без URL.** Обязанность привести адрес висит на сетевом способе распространения, а не на маркере. П. 5.8.3: «Для электронных ресурсов сетевого распространения обязательным является примечание об электронном адресе ресурса в сети Интернет и дате обращения»; форма — п. 5.8.6.4 в): `— URL: … (дата обращения: ДД.ММ.ГГГГ)`. Для электронных журналов п. 5.8.6.4 г) допускает дату публикации вместо даты обращения. Но тот же п. 5.8.3 для локальных носителей требует другого: «Для электронных локальных ресурсов обязательным является примечание об источнике основного заглавия» — CD-ROM и флеш-карта тоже `электронный`, и URL им не положен. Поэтому валидатор (`electronic-no-url`) ветвится: при `medium=electronic` DOI служит эвристическим признаком сети и отсутствие URL даёт `error` (это не доказательство носителя); признаки локального носителя (CD-ROM, DVD, флеш, электрон. опт. диск) — замечания нет; иначе — `warning`. Недоступность URL не делает электронный ресурс печатным. Не меняй носитель и не убирай область ради сокрытия отсутствующего адреса: найди проверенную точку доступа или явно укажи, что запись неполна. Печатную версию можно описывать только по данным именно этой версии.
6. **Диапазон страниц — короткое тире** `–`, не дефис. Инициалы — с пробелом: «И. И.», не «И.И.».
7. **Диссертация в 7.0.100** требует шифр специальности, её название в кавычках, форму степени и ПОЛНОЕ имя автора в сведениях об ответственности.

## Повторные ссылки (7.0.5)

`repeat_reference` или `gost_ref.api`:

- `ibid` — «Там же. С. 25.» только если это та же работа подряд;
- `op_cit` — «Иванов И. И. Указ. соч. С. 364.» когда между ссылками были другие;
- `short` — «Иванов И. И. Начало заглавия … С. 212.» если у автора в работе несколько трудов;
- `cited_from` — «Цит. по: …» только когда первоисточник недоступен. Доступен — ссылайся на него.

## Что показать пользователю

Две готовые строки — сноску и запись для списка, — под ними тип источника по-русски (и чем его заменить, если уверенность не высокая), затем коротко: замечания валидатора уровня `error` и `warning`, поля, которые пришлось оставить пустыми, происхождение полей из документа (страницы), расхождения с исходной записью и поля, взятые из внешней базы (с названием базы). Не прятать неопределённость в гладкую строку.
